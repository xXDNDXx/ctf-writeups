    The Approach¶

    Every write-up in this collection follows the same professional discipline:

    • Full kill chain — first nmap scan to root shell, nothing skipped
    • The "why" for every command — methodology over answer-pasting
    • Dead ends documented — the path to the flag is the lesson
    • Remediation for the blue team — I know what defenders see; my fixes reflect that
    • Flags behind spoiler toggles — attempt the machine first, compare notes after

    Spoilers below

    Every write-up contains full commands, source code, and flags. Attempt the machine on your own first — then come back to compare notes or get unstuck.

    Publication policy

    Only write-ups for retired Hack The Box machines are published here, in line with HTB's disclosure rules. No active machines, ever.

    Methodology in five phases¶

    PHASE 01 Reconnaissance Map the attack surface: full-range nmap, version fingerprinting, every scan saved as evidence. Never trust the first 1000 ports.

    PHASE 02 Enumeration Work the findings, not the checklist. Every discovered service gets deep enumeration before moving on.

    PHASE 03 Exploitation Identify the vulnerability class first, verify the PoC, prefer manual before Metasploit. Understand why it works.

    PHASE 04 Privilege Escalation sudo -l first, SUID, cron, internal services, creds on disk — every hit verified against GTFOBins/LolBAS.

    PHASE 05 Documentation Write during the box, not after. Every command gets its why. Dead ends stay in. Remediation for the blue team.

    RULES OF ENGAGEMENT Rules I don't break No flag copying. No active machines. No random attacks — every action maps to a finding or a hypothesis. Ethics are not optional.
